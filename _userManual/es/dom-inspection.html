Inspección del DOM

Usa la inspección del DOM antes de construir una rutina cuando aún no conoces los selectores de la página.

Inspección básica

$Body = @{
    targetUrl = "https://dev.example.com/login"
    waitUntil = "domcontentloaded"
    includeRenderedHtml = $false
    includeHiddenControls = $true
    includeConsole = $true
    includeNetwork = $false
    redactSensitiveValues = $true
} | ConvertTo-Json -Depth 20

$Inspection = Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:3000/v1/explorations/inspect-dom" `
    -Headers $Headers `
    -ContentType "application/json" `
    -Body $Body

Campos de control

Cada control puede incluir:

  • index, tag, id, name, type, role, className
  • visible, disabled, readonly
  • text, labelContext
  • attrs, selectors, rect

Consejos para elegir selectores

Prefiere selectores estables en este orden:

  1. id único.
  2. data-testid, si está presente en attrs.
  3. Selectores de input con nombre, como input[name="email"].
  4. Selectores de rol o etiqueta accesible solo si los conviertes en selectores CSS admitidos por ScrapForAI.
  5. Selectores de clase solo cuando sean estables y no generados.

Evita:

  • Rutas CSS generadas y profundas.
  • Selectores basados en un diseño inestable.
  • Controles ocultos, salvo que los necesites intencionalmente.
  • Texto que cambia según el idioma o el rol del usuario.

Precaución con el HTML renderizado

includeRenderedHtml es false de forma predeterminada. Si se establece en true, la respuesta incluye sensitiveOutput: true y una advertencia. El HTML renderizado puede contener estado oculto de la aplicación incluso después de la sanitización.

Usa esto solo cuando
  • Los controles del DOM y el texto del cuerpo no sean suficientes.
  • Estés inspeccionando una página de prueba controlada.
  • No estés manejando secretos reales de producción.
