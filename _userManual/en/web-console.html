Guides

Web console

A built-in browser console for reviewing run history, editing configuration, and checking service status — served by ScrapForAI itself, with no separate app to install.

Enabling the console

Set UI_ENABLED=true in your .env and open the console at:

http://127.0.0.1:<PORT>/ui/

Installed builds ship with the console on by default. Visiting the server root (/) redirects there.

Signing in

You sign in with your API key. The server exchanges it for an httpOnly; SameSite=Strict session cookie, so the key itself is never stored in the browser or readable by page JavaScript. Signing out, or restarting the server, ends the session.

Cookie-authenticated writes also carry an X-ScrapForAI-UI: 1 header that cross-origin pages cannot set — this is what keeps the session cookie from reintroducing CSRF. See the Security model for the full rationale.

Run history

The History screen lists every past run, newest first, with pass/fail counts across the top and filters for status, scenario and free text.

Run records and the heavy evidence they point at are kept on two independent schedules: the compact index survives for HISTORY_RETENTION_DAYS (90 by default), while screenshots and traces are pruned after ARTIFACT_RETENTION_HOURS (4 by default).

Click any row to open its detail: the step-by-step breakdown, screenshots, console errors and network failures. When the evidence has already been pruned, the record still opens with an “evidence expired” note instead of an error.

Configuration

The Configuration screen edits .env from the browser, grouped into Safety, Limits, Runtime and History.

  • Locked fields — SCRAPFORAI_API_KEY, the origin allowlists, ALLOW_EVALUATE and HOST — are shown but cannot be changed from a UI session alone. Changing them requires presenting the API key as a bearer token, so a hijacked session cannot widen the SSRF allowlist or enable arbitrary in-page JavaScript.
  • Restart-required fields are labelled as such. Most configuration is read once at startup, so the console writes .env (backing up to .env.bak) and tells you when a restart is needed for a change to take effect.
  • A red banner appears whenever ALLOW_EVALUATE is on, because that setting permits arbitrary JavaScript in the target page.

Status

The Status screen reports the running service and its storage: listen address, uptime, browser engine, active sessions, data and artifact directories, disk usage, and the retention windows. It surfaces a warning if the service is listening on 0.0.0.0 or if ALLOW_EVALUATE is on.
