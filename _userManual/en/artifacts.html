Artifacts & evidence

Where job output is written on disk, how screenshots and traces are controlled, and the structure of the evidence object in results.

Artifact layout

Each job gets its own folder:

artifacts/
  job_<id>/
    result.json
    screenshots/
      failure.png
      custom-name.png
    trace.zip

Screenshot behavior

Controlled by options.screenshots:

ValueBehavior
offNo screenshots are saved.
onFailureFailure screenshot is saved when a step fails. Named screenshot steps also save when screenshots are not off.
alwaysNamed screenshots save, and failure screenshot saves on failure.

Trace behavior

{
  "options": {
    "trace": true
  }
}

When enabled, ScrapForAI saves a Playwright trace to:

artifacts/job_<id>/trace.zip

Result file

The API response is also saved to:

artifacts/job_<id>/result.json

Evidence object

{
  "screenshots": [],
  "tracePath": "artifacts/job_abc123/trace.zip",
  "console": [],
  "consoleErrors": [],
  "pageErrors": [],
  "network": [],
  "networkFailures": [],
  "unexpectedExternalRequests": [],
  "domTextSnapshot": "text...",
  "finalUrl": "https://dev.example.com/dashboard"
}

Full result shape

The top-level exploration result includes:

FieldDescription
jobIdArtifact folder name.
scenarioNameEchoed from the request, if provided.
statuspassed or failed.
startedAt / finishedAt / durationMsTiming for the whole job.
targetUrl / finalUrlRequested and resulting URL.
callerEchoed caller metadata, or null.
failedStepIndexIndex of the step that failed, when applicable.
errorHigh-level { type, message } when failed.
stepsArray of per-step results: index, id, label, action, status, timings, and error.
extractedMap of names to values saved by extractText, extractAttribute, evaluate, or watch.
evidenceThe evidence object described above.

Artifact retention

Old artifact folders are pruned when a new artifact store is created. The cutoff is controlled by:

ARTIFACT_RETENTION_HOURS=4
