Step actions reference

Every supported step action, what it does, its key fields, and detailed usage for the actions with extra structure.

Collect action

collect.what can include: console, network, domText, url, pageErrors.

{
  "action": "collect",
  "what": ["console", "network", "domText", "url", "pageErrors"]
}

Console, network, and page error collectors are registered for the job. The collect step mainly controls extra snapshots such as DOM text and final URL.

Assertion operators

assertCount supports: =, !=, >, >=, <, <=.

{
  "action": "assertCount",
  "selector": "[data-row]",
  "operator": ">=",
  "count": 1
}

waitForElapsed

Use waitForElapsed when the application requires a minimum time gap between actions.

[
  {
    "id": "clicked-send",
    "action": "click",
    "selector": "#send-code"
  },
  {
    "action": "waitForElapsed",
    "sinceStepId": "clicked-send",
    "minElapsedMs": 3000,
    "timeoutMs": 5000
  },
  {
    "action": "click",
    "selector": "#resend-code"
  }
]

The sinceStepId must reference an earlier step ID.

setViewportSize

Use setViewportSize to resize the browser mid-run — for example, to check a responsive layout after starting at desktop size. options.viewport (see routine options) controls the size at job start; this step changes it for subsequent steps.

[
  {
    "action": "goto",
    "url": "$targetUrl"
  },
  {
    "action": "screenshot",
    "name": "desktop"
  },
  {
    "action": "setViewportSize",
    "width": 390,
    "height": 844
  },
  {
    "action": "screenshot",
    "name": "mobile"
  }
]

Width and height each accept 50–4096 pixels.
