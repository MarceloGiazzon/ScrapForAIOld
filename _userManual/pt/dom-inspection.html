Inspeção do DOM

Use a inspeção de DOM antes de montar uma rotina quando você ainda não conhece os seletores da página.

Inspeção básica

$Body = @{
    targetUrl = "https://dev.example.com/login"
    waitUntil = "domcontentloaded"
    includeRenderedHtml = $false
    includeHiddenControls = $true
    includeConsole = $true
    includeNetwork = $false
    redactSensitiveValues = $true
} | ConvertTo-Json -Depth 20

$Inspection = Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:3000/v1/explorations/inspect-dom" `
    -Headers $Headers `
    -ContentType "application/json" `
    -Body $Body

Campos de controle

Cada controle pode incluir:

  • index, tag, id, name, type, role, className
  • visible, disabled, readonly
  • text, labelContext
  • attrs, selectors, rect

Dicas de seleção de seletor

Prefira seletores estáveis nesta ordem:

  1. id único.
  2. data-testid, se presente em attrs.
  3. Seletores de input nomeados, como input[name="email"].
  4. Seletores de papel (role) ou rótulo acessível, apenas se convertidos em seletores CSS suportados pelo ScrapForAI.
  5. Seletores de classe apenas quando forem estáveis e não gerados.

Evite:

  • Caminhos CSS gerados e profundos.
  • Seletores baseados em layout instável.
  • Controles ocultos, a menos que você precise intencionalmente deles.
  • Texto que muda por localidade ou papel do usuário.

Cautela com HTML renderizado

includeRenderedHtml tem padrão false. Se definido como true, a resposta inclui sensitiveOutput: true e um aviso. O HTML renderizado pode conter estado oculto da aplicação mesmo após a sanitização.

Use isso apenas quando
  • Os controles de DOM e o texto do corpo não são suficientes.
  • Você está inspecionando uma página de teste controlada.
  • Você não está lidando com segredos reais de produção.
