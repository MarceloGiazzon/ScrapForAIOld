Solução de problemas

Modos de falha comuns e como diagnosticá-los, desde falhas no health check até esperas de resposta com comportamento inesperado.

O endpoint de saúde falha

Verifique:

  • O container ou servidor de desenvolvimento está em execução?
  • A porta 3000 já está em uso?
  • A validação de ambiente falhou durante a inicialização?
  • O Docker Desktop e a imagem do Playwright estão disponíveis?
docker logs scrapforai-api
docker compose ps

Endpoint protegido retorna 401

Verifique:

  • O cabeçalho está presente.
  • O formato do cabeçalho é exatamente Authorization: Bearer <chave>.
  • A chave de API corresponde a SCRAPFORAI_API_KEY.
  • A chave de API tem ao menos 16 caracteres.
$Headers = @{ Authorization = "Bearer $ApiKey" }

A requisição retorna 400 ValidationError

Verifique:

  • O corpo JSON é válido.
  • Os campos obrigatórios existem.
  • targetUrl é uma URL válida.
  • Os nomes das ações de passo estão escritos corretamente.
  • steps não está vazio e não excede MAX_STEPS_PER_JOB.
  • Passos baseados em valor incluem exatamente um de value, valueFromCredential ou valueFromVariable.
  • As condições de espera incluem exatamente uma condição.

A resposta inclui detalhes:

{
  "error": {
    "type": "ValidationError",
    "message": "Invalid exploration request",
    "details": [
      {
        "path": "steps.0.selector",
        "message": "Invalid input"
      }
    ]
  }
}

A URL é rejeitada

Verifique:

  • A origem da URL está listada em ALLOWED_TARGET_ORIGINS.
  • O esquema corresponde. http:// e https:// são origens diferentes.
  • A porta corresponde. http://localhost:3000 e http://localhost:5173 são origens diferentes.
  • Os redirecionamentos permanecem em origens permitidas.
ALLOWED_TARGET_ORIGINS=http://localhost:5173,https://dev.example.com

A rotina retorna 429 TooManyRequests

O número de jobs ativos atingiu MAX_PARALLEL_JOBS.

Opções de correção:

  • Aguarde os jobs atuais terminarem.
  • Aumente MAX_PARALLEL_JOBS.
  • Reduza a duração do job.
  • Reduza a concorrência do cliente.

O passo expira (timeout)

Verifique:

  • O seletor está correto.
  • O elemento está dentro de um iframe e precisa de frame.
  • A página ainda está carregando.
  • A aplicação precisa de um waitFor ou afterWaitFor mais preciso.
  • STEP_TIMEOUT_MS está baixo demais para o ambiente.

Use a inspeção de DOM para encontrar seletores e um screenshot de falha para ver o estado da página.

waitForResponse perde uma resposta

Use afterWaitFor.response na ação que dispara a resposta:

{
  "action": "click",
  "selector": "#submit",
  "afterWaitFor": {
    "response": {
      "urlContains": "/api/save",
      "status": 200
    },
    "timeoutMs": 10000
  }
}

Isso arma o listener de resposta antes do clique.

evaluate ou watch é rejeitado

Verifique:

ALLOW_EVALUATE=true

Verifique também:

  • O tamanho do script está abaixo de MAX_EVALUATE_SCRIPT_CHARS.
  • O script retorna valores seguros para JSON.
  • O script é concluído antes de EVALUATE_TIMEOUT_MS.

Screenshots ausentes

Verifique:

  • options.screenshots não é off.
  • Um passo screenshot tem um name válido.
  • O job alcançou o passo de screenshot.
  • O diretório de artefatos é gravável.

Trace ausente

Verifique:

  • options.trace é true.
  • O job iniciou o Playwright com sucesso.
  • O diretório de artefatos é gravável.
  • O resultado inclui evidence.tracePath.

Requisições externas inesperadas

Se unexpectedExternalRequests contiver itens:

  • Confirme se a aplicação legitimamente chama essas origens.
  • Adicione as origens esperadas a ALLOWED_RESOURCE_ORIGINS.
  • Investigue chamadas inesperadas de terceiros em desenvolvimento ou QA.

A inspeção de DOM retorna sensitiveOutput true

Isso acontece quando includeRenderedHtml é verdadeiro. Trate a resposta como sensível. Prefira manter includeRenderedHtml falso, a menos que você realmente precise do HTML.
